# Reminder Timezone Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix "remind me at 9am my time" being silently (and sometimes incorrectly) interpreted as UTC. The LLM reasons in a configured local timezone it's explicitly told "now" in; deterministic code (stdlib `zoneinfo`) handles the local→UTC conversion for storage and back for display.

**Architecture:** Three tasks, each independent to write but composing in order: `config.py` (new `TIMEZONE` setting) → `brain.py` (`_now()` reports local time, prompt tells the model not to convert to UTC itself) → `reminder_plugin.py` (`_parse_when()` does the local→UTC conversion, a new `_format_local()` helper converts back for display).

**Tech Stack:** Python 3.11+, stdlib `zoneinfo` (3.9+, no new dependency), `pytest`. No new dependencies.

## Global Constraints

- One global `TIMEZONE` setting (default `"UTC"`), not per-owner — household-bot scale, same reasoning as the shared shopping list.
- `TIMEZONE` is validated as a real IANA name at startup (`zoneinfo.ZoneInfo(...)`, catching `ZoneInfoNotFoundError`) — a typo'd timezone must fail loudly at import time, not silently misbehave later.
- The LLM's job changes from "compute an absolute UTC datetime" to "compute an absolute datetime in the local timezone you were already told 'now' is" — it must never be asked to also convert timezones itself.
- `reminders.py`'s storage format is unchanged — `fire_at` stays a UTC ISO string with `timespec="seconds")`. Only what feeds into it (now locally-aware) and what reads out of it for display (now locally-formatted) changes.
- Existing tests that pass an already-offset-aware ISO string to `_parse_when()` (e.g. `_future_iso()`'s output) must keep passing unchanged — the local-timezone-assumption code path only activates for a *naive* (no-offset) input, which is what the LLM will now actually send but nothing in the existing test suite happens to construct.

```python
def _parse_when(when):
    if not when:
        return None
    try:
        parsed = datetime.fromisoformat(when)
    except ValueError:
        return None
    if parsed.tzinfo is None:
        parsed = parsed.replace(tzinfo=ZoneInfo(config.TIMEZONE))
    parsed_utc = parsed.astimezone(timezone.utc)
    if parsed_utc < datetime.now(timezone.utc) - _GRACE:
        return None
    return parsed_utc
```
